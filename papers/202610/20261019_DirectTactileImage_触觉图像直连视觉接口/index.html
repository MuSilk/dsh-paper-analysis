把触觉塞进视觉接口：Astra 在插孔与抽拔上压过专用触觉策略

引子

桌上一个带孔的方块，轴要从孔口进去，孔的方向被工件本体挡住，固定相机只看得见轴的上端和方块正面。在成功的那条轨迹里（Insert Hole，种子 1000028），两条触觉带的斜率方向相反，轴上端在画面里也偏了一点，模型把进入方向翻到负 X 一侧，保持轴尖抵着孔口转动，再顺着推断出的孔轴推进。同一个任务的纯视觉版本按参考轨迹试正 X 方向的斜坡，反复在同一深度上转，没有把轴送进去。差别不在抓取精度，而在有没有读到孔口斜面朝哪边这条局部几何，固定相机看不见孔内壁，指尖的形变图看得见。

触觉也不是万能的。重块被读成轻块的那条失败轨迹（Weight Classify，种子 10038）里，模型把抬升时很小的接触变化当成轻物证据，把重块放进了蓝色托盘，而抓位、开口和运动都会改变图像，小剪切并不等于轻载。Empty-Can Selection 的另一条失败轨迹（种子 10034）第 370 步才选定正确的罐子，第 390 步开始最后的抓取提升，400 步的动作预算已经不够完成搬运。

这些轨迹指向一个分歧。接触丰富操作长期被当作专用触觉策略的地盘，判材料、判滑移、判插入方向都默认要有触觉预训练的表征和动作头。这篇论文问的是另一件事：一个只带视觉接口的通用多模态模型，能不能把触觉图像当普通图片读，靠少量示范把接触证据接到动作上。

问题背景

触觉在这条线上至少指三件不同的事：传感器吐出的原始图像、从图像学出来的表征、把表征接到动作上的策略。论文动的是第一层与第三层之间的接口，绕开了第二层。

概念 指什么 本文的位置
接触丰富操作（contact-rich manipulation） 成功依赖局部几何、滑移与材料属性的操作，如插入、抽出、易碎件抓取 评测范围是 8 个 UniVTAC 任务加 11 个 OpenViTac 任务
视触觉传感器（vision-based tactile sensor） 以 GelSight 为代表，把接触几何与形变编码成图像 输入里的左右指触觉 RGB 图，走模型已有的视觉接口
专用触觉策略（specialist tactile policy） 在触觉数据上预训练表征或动作头，按任务族训练 被比较的对象：FTP-1、SimpleTouch、OpenVTLA 等
上下文策略（in-context policy） 不更新权重，把示范与在线记录放进上下文，由模型直接出动作 Astra 的工作方式，交互结构沿用 RoboICL
执行回执（execution receipt） 一条命令执行后的记录，与命令本身分开 每轮进入上下文，区分命令发完了与任务推进了
动作注（action note） 决策时附的短文字，说明模型对当前接触的判断 轨迹分析的证据来源之一

已有路线可以分三派，卡点各不相同。

路线 代表工作 做法 卡在哪里
先学触觉表征再接到动作 VITaL、3D-ViTac、ViTacFormer、Sparsh、AnyTouch、T3 在触觉数据上预训练可迁移的接触表征，再为任务族训练策略 表征与传感器、抓取构型绑定，换传感器要重新对齐
把触觉塞进预训练 VLA Tactile-VLA、VLA-Touch、AT-VLA、OpenVTLA 在 VLA 里加触觉编码分支或双层次触觉反馈 需要额外的模态对齐训练，触觉与视觉主干各一套
通用多模态模型直接当策略 GPT-as-Policy、RoboICL、RoboDawn、RoboProbe 用示范与在线记录组成上下文，输出末端与夹爪命令 输入一直是场景图，接触证据没有入口

三派的共同前提是触觉需要自己的入口。前两派为触觉加一层编码器与一批对齐数据，第三派绕开训练却只喂场景图。如果触觉传感器的输出本来就是图像，通用模型的视觉接口为什么不能直接吃它，这个问题一直没被回答。

核心思想

借的框架是 RoboICL 的 observation-action-receipt-observation 语法。一次交互由观测、动作、回执、下一帧观测四段组成，示范与在线经验用同一种结构表达。触觉图像被放进观测这一格，位置与场景图并列，输入类型没有增加。

原来那个问题，通用模型需不需要一套触觉专用的感知与策略，被换成了通用模型能不能在示范上下文里把接触图像与它前后的动作、结果对上。这个替换可检验：同一批场景种子、同一套示范块、同一套动作接口，只把触觉图拿掉或放回去，成功率之差就是触觉的边际贡献。

RoboICL 在这里只承担接口约定；论文没有改 Astra 的权重，也没有为触觉加适配层。

方法

机制一：接触图像直连视觉接口（Tactile Images as Visual Input）

治的失败是触觉被当成新模态。一旦触觉需要独立编码器，换传感器、换抓取构型、换任务都要重新对齐，通用模型的视觉能力也用不上。

第 \(t\) 轮决策的输入是任务指令 \(g\)、机器人状态 \(x_t\)、场景图 \(I_t\)，以及视触觉设定下附加的左右指接触图 \(T_t\)。场景图给全局位姿与目标几何，接触图给局部形变，状态给本体感觉，三者合起来才能把看到的一次接触与准备发出的位移联系起来。相机严格按 benchmark 官方配置：UniVTAC 八个任务里六个只有固定相机，Lift Can 与 Insert Tube 额外给腕部；OpenViTac 每个任务都给固定加腕部。视觉独跑（V）从示范和在线观测里都删掉接触图，其余输入不动。

动作由同一个上下文生成：

\[A_t \sim \pi(\cdot \mid g, \mathcal{D}, \mathcal{M}_t, x_t, I_t, T_t),\qquad a=(\Delta p, \Delta r, u)\]

\(\Delta p\) 与 \(\Delta r\) 是平移与旋转增量，\(u\) 是夹爪目标，合起来七维；V 设定里 \(T_t\) 缺席。

机制二：示范块与交互记忆（Demonstration Blocks and Interaction Memory）

治的失败有两种：少样本下模型不知道某种接触之后通常发生什么，长回合里它忘了前面试过哪些方向。

示范上下文 \(\mathcal{D}\) 由成功轨迹里切出的块组成，一块包含起点的观测与状态、\(H\) 步动作、执行回执、结束时的观测与状态。切块用 RoboICL 放出的确定性选择器离线完成，按时间目标分散、互不重叠、跳过无效动作窗。十二个任务用一条示范切十二块，六个分类或选择任务用两条示范各五块，Insert Block v2 用三条示范、每个形状一条、各五块。\(H\) 按轨迹长度逐任务固定，取值在 4 到 10 之间，例如 Weight Classify 两条示范的起点是 \(\{0,33,66,99,132\}\) 与 \(\{0,35,69,104,139\}\)，\(H=5\)。

在线记忆 \(\mathcal{M}_t\) 同构：分布式锚点保留较早阶段，最近一次交互保留最新结果，被省略的区间用显式缺口标记，示范块整局常驻。

机制三：七维动作与执行回执（Seven-Dimensional Commands and Execution Receipts）

治的失败是把命令完成当成任务完成。插入命令发出去，物体仍可能卡在孔沿上。

benchmark 适配层把七维命令转成仿真器接口并记录执行，回执与下一帧观测进入下一次决策；一条命令被执行只说明动作发出去了，物体有没有到位由新观测判断。Insert Block v2 的一条成功轨迹在释放之后零件仍停在孔口，模型把它当作未完成，重新抓取、抬升、再对位。仿真侧的协议是 60 Hz 命令、每条命令两个 120 Hz 子步，模型每次决策附一条短动作注，说明它把接触图读成了什么。

实验

设置

评测覆盖 8 个 UniVTAC 任务与 11 个 OpenViTac 任务，合计 19 个。采样用 10% 分层抽样、种子 42，每个输入设定含 80 个 UniVTAC 与 130 个 OpenViTac 场景种子，共 210 个，每任务十个，Insert Block v2 按三个形状各十个共三十个。模型是 GPT-6 Astra，推理强度 xhigh；示范来自 UniVTAC 放出的训练记录，OpenViTac 的示范用官方脚本专家在训练模式下采集。基线取自各自 benchmark 的已发表结果，Astra 在自己抽的场景上评测，两边不是同一批 episode。成功率按任务报告，均值等权，Insert Block v2 的三十个场景先聚成一个任务分。Grasp Chip 判据被放宽：完整芯片被抓取、搬运、在目标区域以稳定支撑放置即算成功，不再要求特定的释放回撤顺序。

反常结果与参数敏感性

第一个反常是触觉在两边的价值差一个数量级，17.5 对 1.2。论文的解释是相机配置：UniVTAC 六个任务只有固定相机，OpenViTac 每个任务都有固定加腕部两路视图，视觉线索更足时触觉的边际价值下降。这与 V 设定的表现一致，Astra 纯视觉在 OpenViTac 已到 80.6%，高于 OpenVTLA 的 68.7%。

第二个反常是加了触觉反而变差，Weight Classify 从 50% 掉到 40%，Empty-Can Selection 从 70% 掉到 50%，Insert Tube 从 100% 掉到 90%，Insert Block v2 从 76.7% 掉到 70%。论文检查了三对 V 成功而 V+T 失败的 Weight Classify 样本，纯视觉那条路是松开夹爪看可见滑移判重量，触觉版本把弱剪切读成轻载。Empty-Can Selection 的问题在预算，反复比较接触条件让后面的搬运没有时间。

第三个反常是饱和。触觉设定下 19 个任务里 13 个达到 90% 以上，其中 9 个在这批采样里满分；Insert USB 在 Astra 两种设定下都是 100%，同一张表里 OpenVTLA 是 27%。这些天花板让均值越来越难区分强弱策略。

参数敏感性只有一处硬数字：每任务十个 episode，单个 episode 的得失就值十个百分点；抽样只用一个种子 42；\(H\)、示范条数、推理强度都没有扫描，Grasp Chip 判据放宽对 OpenViTac 均值的影响也没有单独报告。失败模式给得倒具体，Insert Block v1 的一条失败轨迹从第 240 步起累计俯仰增量约 51.6 度，插入仍未完成；Insert HDMI 的一条失败轨迹用了 600 个动作与 120 次模型决策，第 235 步的注说触觉图轴向符号不确定，第 270 步又转回竖直解释，诊断始终没收敛成有效的修正。

超过 120 秒的响应分别占 0.76% 与 0.47%。一次响应能出多条动作，下一条依赖观测的修正仍要等下一次响应回来，尾延迟直接拖慢整条闭环。动作预算也是硬约束，Empty-Can Selection 的 400 步、Insert HDMI 的 600 步与 120 次决策，都按 benchmark 上限截断。

我的判断

站得住的地方在接口选择。触觉图像本来就是图像，视觉主干在预训练里处理过大量纹理、形变与遮蔽关系，把接触图放进同一个输入槽位，等于让读触觉复用读图的能力，代价只是一次调用里多两张图。证据不止均值，需要根据接触改变动作的几类轨迹行为是逐帧可读的，卸载扭转、保持入口接触转向、双边接触后停闭合、释放后复查，场景图支撑不了这些决定。

评测可比性要先打折。基线是别人在完整 episode 集上报的数，Astra 用 10% 抽样、每任务十个 episode，一个 episode 值十个百分点，两边还不是同一批场景；Grasp Chip 判据被放宽，而这一项在两种设定下都是 100%，放宽只会抬高 OpenViTac 均值。在这三个条件下，1.2 个百分点的 OpenViTac 增益落在噪声尺度里，既不能当作触觉无效的证据，也不能当作有效的证据。

成本论文报了但没展开。7,505.05 元是评测开销，不是部署成本；真正要看的是每次决策 15.4 秒的中位响应与 P99 的 110.7 秒，这个节奏只适合慢速、可停顿的桌面任务。示范准备的开销被排除在计费之外，论文没有给这部分数字。

没做的实验很清楚：\(H\)、示范条数、示范块数、推理强度档位都没有敏感性分析，只有仿真没有真机，触觉传感器的型号、分辨率与标定流程没有交代，抽样种子只有一个。这些空白里 \(H\) 与示范条数最可能影响结论，因为它们同时改变上下文长度与 token 成本。

要往下推，三件事按顺序做。先造视觉不可区分的对照任务，同形不同质量、同色不同摩擦的块，把看出纹理与摸出物理量分开；再把探测预算写进策略，给显式的停止规则与剩余动作计数；最后在真机上先测标定误差与执行延迟，仿真里的干净接触图不会原样出现。

触觉进入通用模型的门槛在接口，不在数据量。这篇论文拆掉了接口这一半，剩下的一半在评测设计与闭环时延上。
