# 工具自己写：VLM agent 接管双臂机器人，赢在读场景，输在接触那一下

## 引子

桌面上一块 T 形积木，一块 T 形垫子。双臂机器人要把积木推到垫子上，结束时两只手臂回 home，误差不超过 7 mm 和 7°。整个 episode 给 600 个动作步，约 24 秒机器人时间。

机器人只有三路 640×480 的 RGB 相机：一个固定在头部，两个装在手腕上，随末端一起走。没有深度图。夹爪的每个动作都以世界坐标的米和度为单位，任何一次抓取或放置，位置要准到一厘米左右。

布局 2 的第 4 轮里，agent 要量积木顶面的高度。工具从头部和腕部两个视角估计面积，要求两边的面积比落在 0.85 以上，否则拒绝回答。十次请求全部被拒，agent 退回去用桌面高度 0.765 m，而积木顶面在 0.780 m。15 mm 的高度误差把投影轮廓挪了 10 mm。第一次搬运其实只偏了 3.2 mm，落在限制之内，但释放检查用了同一个错误高度，报出 12.5 mm，agent 连改三次，最终停在 13.6 mm 外。

这段失败里不缺信息：两个视角都拍到了积木，标定也在。错在测量代码把「面积」定义成网格计数，而两个相机的像素尺度不同。论文要问的问题由此展开：一个编码 agent 拿着一条命令行，能自己把这类工具写到什么程度，又会在哪里停住。

## 问题背景

这篇论文把「agent 控制机器人」拆成几层，先对齐用词。

| 概念 | 指什么 | 在这篇里对应什么 |
|---|---|---|
| 薄壳（thin harness） | 把命令行翻译成关节运动的服务器，不做任何决策 | 只提供 `robo` 一条命令、`obs/` 目录和约 60 行手册 |
| 工具（tool） | 带 `tool.py` 与 `interface.md` 的目录，给 `robo` 增加子命令 | 负责从 RGB 量出三维位置，跨 episode 保留 |
| episode 日志 | 每条命令、每帧相机图、agent 的对话记录 | 优化轮的唯一证据来源 |
| 优化轮（optimizer round） | 失败后诊断、改一个工具、跑测试、重试同一布局 | 中位 6.3 分钟一轮 |
| 动作步（action step） | 官方基准里的一次 `take_action` | 200 到 1900 步，push T 是 600 步 |
| 布局（layout） | 种子内一组固定的物体位姿与桌面材质 | 每个种子 30 到 75 个布局 |

已有路线大致三派。

| 路线 | 做法 | 卡在哪里 |
|---|---|---|
| 学出来的策略 | VLA 或世界动作模型从大量演示里直接输出动作 | 需要成规模的机器人数据，换任务要重训；在遮挡与杂乱场景里退化快 |
| 固定接口的 VLM agent | 让 VLM 在别人写好的薄壳上选末端目标点 | 接口定死了能做什么，模型的空间判断又不准，天花板由接口决定 |
| 让模型写机器人代码 | Code as Policies、ReKep、MOKA、RoboCodeX 之类，按指令生成程序或关键点 | 程序用完即弃，感知与控制原语仍由人写，模型学到的东西留不下来 |

三派合起来留下一个问题没有回答：如果不许 agent 改脚手架、也不许换模型，只许它写和修自己的工具，它能在这套基准上走到多高，失败又集中在哪一类物理交互上。论文用 42 个任务和一张按接触类型划分的能力图回答这个问题。

## 核心思想

编码 agent 在软件仓库里的循环是现成的：读代码、跑、读报错、改一处、跑测试、通过后修复留下。论文把这三步搬到机器人上，只做了三个替换。

第一个替换是把「技能」换成「工具库」。agent 不写一次性任务脚本，它维护一组带接口说明和单元测试的小函数；每次失败只改其中一个函数，改完在同一个布局上重跑。第二个替换是把「深度」换成「标定几何」。像素加内外参就是一条世界坐标下的射线，射线再补一个约束，比如已知高度的桌面、块顶平面，或者第二个视角，就得到三维位置。第三个替换是把「总分」换成「接触分类」。每个任务被打上物理标签与决策标签，成功率的差异按标签拆开看，边界才显形。

一句话概括：论文把「VLM 能不能直接当机器人策略」换成了「一个不改模型的 agent，靠可测试的测量工具能覆盖哪几类接触」。

## 方法

### 机制一：薄壳（Thin Harness）

治的是「接口替 agent 做决定」这种失败。容器里的 agent 是一个未经改动的编码 agent 命令行程序，没有网络、没有 API key、没有宿主机目录，出网流量走一个出口代理，只放行模型端点和薄壳自己的路由。

它拿到的只有一个可执行文件 `robo` 和一个按需刷新的 `obs/` 目录。目录里是三路 640×480 图像，每台相机的内参和在世界系下的位姿，两个工具中心点（TCP）的位姿与关节角。没有深度图。基础命令是 `move`（沿世界轴平移 TCP，每轴最多 0.20 m）、`rotate`（绕 TCP 旋转，每轴最多 90°）、`point`、`gripper`、`home`、`wait`、`obs`、`status`、`done`。

服务器对每条命令做校验，按 2 cm 间距插值出直线笛卡尔路径，逐点用 cuRobo 解逆运动学，按机器人官方限位做梯形速度规划，再按基准的 25 Hz 采样，走官方 `take_action` 调用。没有运动规划器，也没有机器人本体和桌面之外的碰撞模型。命令返回一个 JSON 记录：

```
{
  "request": ...,
  "plan_ok": true,
  "reached_pose": ...,
  "settled": true,
  "gripper": ...,
  "time_used": ..., "time_left": ...,
  "commands_left": ...,
  "episode_over": false
}
```

失败原因是有限的几种：`ik_unreachable`、`self_collision`、`table_collision`、`workspace_limit`。观测、测量和模型思考都不计步，只有真正执行的 `take_action` 计一步，计数器随每条响应返回。

同一个服务器有两个执行器。direct 执行器在进程内直接驱动仿真，可以 reset、回放，并把真实物体位姿写进一个容器永远收不到的字段；bridge 执行器把服务器包成官方评测客户端的策略，没有 reset，也没有 ground truth。agent 在两边的接口相同，而每个交付的工具都必须在 bridge 下能跑。

### 机制二：标定几何（Calibrated Geometry）

治的是「单目深度不准」这种失败。一个像素加标定得到一条射线，射线本身不是位置，每次测量都要再补一个约束。

第一个约束是桌面。共享工具 `table_plane` 在 episode 内首次调用时测桌面高度，不花步数：它扫一串候选高度，把一台相机的图像按这个高度的平面 warp 到另一台相机，取重投影最一致的解。三台相机两两之间在实验里一致到 1 mm 以内（0.7646 到 0.7656 m）。第二个约束是任何已知高度的水平面，块顶、碗沿、盒子的插槽，量出高度后，穿过像素的射线与这个平面求交就得到点。第三个约束是第二个视角：两台相机看到同一个点，两条射线近似相交，取交点即三角化位置。

对应像素的来源有两种，agent 自己在一对图里点，或者工具内部用模板匹配、轮廓、圆拟合去找。头部相机能看到整张桌子，但常常太远、角度太斜，物体之间还会遮挡。腕部相机能给第二个视角，前提是机器人先把腕部移过去。这一步是机器人运动，会消耗动作步。规则写得很硬：物体的尺寸、位置、高度都必须在当前 episode 里量，不许来自基准的资产、布局、配置文件或日志。

### 机制三：工具即代码（Tools as Code）

治的是「学到的东西留不下来」这种失败。一个工具是一个目录，里面有 `tool.py` 和 `interface.md`。Python 文件声明名字、子命令、参数，以及一个 `run(api, command, args)` 函数，操作对象是 `EpisodeAPI`。这个 API 给出关节角、TCP 位姿、三路带标定的 RGB 图，以及和基础命令相同的运动原语。

工具不能 import 仿真器，不能读物体位姿，只有列在任务的 `enabled_tools.txt` 里才会被加载。不移动机械臂的测量命令免费，因此 agent 可以随便调用；会动臂的命令，包括挪腕部相机去看一眼，返回和基础命令相同的规划判定，并把各阶段列出来。共享池里只有 `pick` 和 `table_plane` 两个工具，循环从不修改它们，其余工具都按任务定制。

交付检查是这一机制的另一半：文件要完整，工具要能加载，`interface.md` 不许出现任务名或物体名。检查用一张禁用词表执行，不通过就回滚这次编辑。这条规则逼着工具写成通用的测量函数，而不是把「egg carton 在 (x, y)」写死。

### 机制四：进化循环（Evolution Loop）

治的是「失败不知道从哪改」这种失败。一个命令跑一个任务、占一张 GPU。循环按布局推进，先用评测种子 0 的前十个布局（Generalization 任务五个标准、五个杂乱，共用同一套工具）。

acting agent 用当前工具尝试这个布局。成功时，optimizer 读一遍轨迹，往 `playbook.md` 追加一小段，记下哪些工具好用、为什么。失败时，它读命令日志、每条命令执行后的相机帧、当前工具代码，把诊断写进 `skill.md`，然后新增或修改一个工具。交付检查通过后，仿真重启，同一个布局再试一次，每个布局最多改五次。十个布局跑完，工具固化，再不启用 optimizer，在十个开发布局和十个新布局上各测一遍。

两个 agent 都是 Codex 加 GPT-6-Astra，推理强度 medium。optimizer 只能写 `tasks/⟨task⟩/` 下的东西，碰不到薄壳、手册和共享池。每次任务的开发预算 12 小时。

## 实验

设置上，基准是 RoboDojo：双臂 ARX X5，Isaac Sim 5.1，42 个任务分五类（Generalization、Memory、Long-Horizon、Precision、Open），展开成 54 个变体。每个任务三个评测种子，一个种子是 30 到 75 个布局，物体位姿和桌面材质在固定规则下变化。成功与否由基准自己的 checker 逐步判定，首次成功即结束。榜单分数是五类等权平均，Generalization 取标准与杂乱两个变体的平均。

对比对象取 2026 年 10 月 14 日的榜单，每个条目在每个种子上跑 50 个 episode；两个最强的学习策略是 VPP2（成功率 32.26%，进度分 39.26，世界动作模型）和 PhysicalRSI（31.38%，36.27，VLA 加语言模型 agent）；30 个学习策略用于杂乱对比。同模型无工具的基线是 GPT-6-Astra 在基准作者写的固定壳里选夹爪目标点，每任务一个种子 50 个 episode（22.48%，28.97）。

主结果是冻结重测：每个任务在种子 0 的十个新布局（第 10 到 19 个）上各跑一集，工具构建时没见过这些布局。重测时 agent 的 prompt 里放了任务描述和基准文档里的评分表，也放了开发阶段的工具使用笔记。硬件是一张 RTX 4090 跑一个 run。

| 系统 | 成功率 | 进度分 |
|---|---|---|
| HexaShell（RGB，冻结工具） | 39.7 | 48.0 |
| VPP2（世界动作模型） | 32.3 | 39.3 |
| PhysicalRSI（VLA + LLM agent） | 31.4 | 36.3 |
| GPT-6-Astra 无工具 | 22.5 | 29.0 |
| 54 个变体朴素平均：HexaShell / VPP2 / PhysicalRSI / 无工具 | 35.4 / 30.6 / 26.1 / 24.3 | — |

逐变体看，HexaShell 有 23 个变体高于 VPP2，中位高 29 点；27 个低于，中位低 23 点。领先的地方集中在「读懂并记住场景」：Memory 65.0%（对手最高 55.6%），Open 50.0%（对手最高 31.0%）。落后的是精确接触：VPP2 在 Precision 上 35.2%，Long-Horizon 37.0%，HexaShell 分别是 31.3% 和 23.8%。六个变体全过十次，十九个变体挂零。

杂乱场景最能看出系统依赖什么。任务本身不变，只在周围加 13 到 18 个干扰物。HexaShell 在开发布局上标准通过 35.0%，杂乱 33.3%，保住 95% 的成功；同模型无工具保住 87%；30 个学习策略只保住 1% 到 68%，中位 18%，VPP2 从 46.4% 掉到 12.6%，PhysicalRSI 从 25.7% 掉到 5.6%。原因在工具做什么：agent 点一个目标像素，工具只测这个物体。折衣服是例外，从 4/5 掉到 2/5，因为它的工具按颜色连通域找布料，旁边有东西就断。

三角化与深度网络的对照用同一套壳、同一个循环、同一个模型，都跑开发布局。下表里三角化一列的榜单分是 38.3，比主表的 39.7 低，因为两者测的布局集不同。

| 类型 | 三角化 成功 / 进度 | 深度网络 成功 / 进度 | 渲染深度 成功 / 进度 |
|---|---|---|---|
| Generalization | 34.2 / 37.7 | 26.7 / 30.0 | 45.4 / 51.5 |
| Precision | 21.3 / 28.4 | 7.5 / 11.9 | 41.3 / 47.3 |
| Long-Horizon | 18.8 / 32.2 | 13.8 / 29.2 | 32.5 / 44.2 |
| Memory | 73.3 / 73.3 | 55.0 / 58.0 | 66.6 / 66.6 |
| Open | 43.8 / 46.6 | 45.0 / 48.1 | 58.5 / 60.7 |
| 榜单分 | 38.3 / 43.6 | 29.6 / 35.4 | 48.8 / 54.1 |
| 54 变体平均 | 35.7 / 40.8 | 27.8 / 33.0 | 47.2 / 52.8 |

三角化比深度网络高 8.7 分。按布局配对，它把深度网络的 57 次失败变成成功，丢掉了 23 次（McNemar 检验，p<0.001）。增益最大的是 push T（从 10 个布局过 4 个变成 10 个）、imitate sorting sequence（1 到 8）、play Xylophone（0 到 6）。损失集中在往圆形容器里放东西的任务上，比如 pour liquid into cup、pour by language、stack bowls，各丢两个布局，这类任务要量出容器边缘。

原因在误差量级。用 8 个任务的 300 帧对渲染深度做参考，Depth Anything V2 Base 在物体像素上的中位误差是头部 41 mm、腕部约 100 mm，即使用桌面把尺度固定住。另外三个网络 Depth Pro 和两个版本的 MoGe 把头部误差压到 20 到 31 mm，腕部仍在 21 到 72 mm。抓取和放置需要大约一厘米。几何没有这个地板：假设成立时，误差只来自标定和像素。渲染深度仍高 10.6 分，差距大部分在紧密插入。

第二视角不是免费的。

| 指标 | 三角化 | 深度网络 |
|---|---|---|
| 用于观察的执行步占比 | 3.6% | 0.7% |
| 出现观察动作的 episode | 180（43%） | 40（10%） |
| 观察步占步数上限的中位比例 | 4.9% | 2.9% |
| 成功数（420 集） | 152 | 118 |
| 步数上限使用中位数 | 70.0% | 63.1% |
| 用掉 75% 以上上限的失败 | 189 / 268 | 228 / 302 |
| 撞到步数上限的 episode | 20 | 26 |
| 发生观察动作的 180 个布局上的成功 | 39 | 22 |

在有观察动作的 180 个布局上，三角化成功 39 次，深度网络 22 次（22 比 5 的不一致对，p=0.002）。其余 240 个布局上差距收窄到 113 比 96。步数并没有因此更紧：用掉四分之三预算的失败比例反而更低（71% 对 75%），撞上限的 episode 更少（20 对 26）。代价分布不均，最贵的是必须重新量出「上一版工具当作固定值」的东西：蛋盒花掉 40% 的步数，硬币槽 16%，这几个任务最终都没成功。付得值的地方回报很高：play Xylophone 花 17% 的步数在观察上，从 0 个布局变成 6 个；push T 花 8%，从 4 个变成 10 个。

能力图把平均数藏起来的分裂摊开：18 个变体在 50% 以上，19 个是 0%。

|---|---|---|---|---|---|
| R 刚性抓放堆叠 | 22 | 36.9 | 44.1 | 50.0 | 30.0 |
| Pu 推、滑、按 | 4 | 60.0 | 67.5 | 92.5 | 24.7 |
| Mv 运动中的物体 | 2 | 33.0 | 30.0 | 40.0 | 43.0 |
| In 紧密插入 | 12 | 1.7 | 1.7 | 8.3 | 28.1 |
| Df 可变形、流体、颗粒 | 6 | 26.0 | 30.0 | 33.3 | 49.4 |
| Ar 铰接物体、工具使用 | 8 | 2.0 | 0.0 | 7.5 | 21.6 |
| 全部 | 54 | 24.3 | 27.8 | 35.4 | 30.6 |

推类到了 92.5%，刚性操作 50.0%，插入只有 8.3%，十二个插入变体里七个挂零。决策标签的影响小得多，只有记忆一项突出，65.0%。VPP2 的画像正好相反：推类 24.7%、刚性 30.0%，插入 28.1%、可变形 49.4%、铰接 21.6%。用渲染深度时插入能到 30.1%，其中 insert key 80%、play stacking toy 73%，换成 RGB 只剩 8.3%；倒液从 59% 到 95% 掉到 0% 到 10%。头部相机一个像素在桌面上覆盖 2 到 3 mm，而插入要求孔和零件在同一帧里对齐到几毫米，能分辨孔的那个腕部视角又必须在夹着零件时获得。

失败怎么结束，也是一条诊断线索。420 集里有 268 集失败，5 集因工具报错提前结束；其余 263 集里 57% 耗尽预算，30% 由 agent 宣布完成但 checker 不同意，13% 在还剩四分之一以上预算时放弃，另有 2 集被 checker 判违规。可变形、铰接、刚性任务的失败 60% 到 77% 是耗尽预算，agent 看得出结果不对，反复重试直到步数用完。记忆任务有一半是宣告成功，agent 以为自己复现了先前状态。运动中物体的典型失败是目标一经过就放弃。宣告失败指向感知或任务规格的缺口，耗尽预算指向执行的缺口。

论文还做了一次「知道 checker 要什么」的对照。早期用渲染深度时，给 optimizer 一份简短的 checker 说明，三个任务从 0% 到 40% 提到 95% 到 100%。这份说明在 RGB 运行里一直保留，开发布局上 press by number 保住 9/10，pour balls into vase 保住 7/10，pour liquid into cup 掉到 1/10，同时把五分之一步数花在观察上。知道检查条件必要，但不充分，工具还得量得准。

## 工程实现细节

手册约 60 行，所有任务共享，工具各自的 `interface.md` 追加在后面。它写清世界系（原点在两臂基座之间的地面，桌面名义高度 0.74 m，真实高度由 `table_plane` 测）、TCP 与开合轴的定义、基础命令、限制（每个 episode 最多 60 条命令，仿真时间按任务限）、JSON 反馈字段、观测结构（三路 640×480 加 `state.json`，含两个 TCP 位姿、关节角、夹爪值和各相机内参外参），以及投影与反投影公式。

几个能照着做的数字：路径插值间距 2 cm，逆解用 cuRobo，时间采样 25 Hz，`wait` 最多 5 s。重测一集中位 739 s，对应 26 s 的机器人时间，几乎全是模型延迟，基准不为延迟计费。

优化轮的成本：769 轮，每任务中位 17 轮；失败后的一轮中位 6.3 分钟，90% 在 11 分钟内；一轮里 optimizer 平均跑 16 条 shell 命令，92% 的失败轮会运行任务自带测试；中位编辑加 118 行、删 6 行（含测试与笔记）。每轮读入 75 万 token，大部分命中缓存，写出 5700 token；总计读 4.87 亿、写 380 万。所有任务合计留下 327 条任务命令、约 7.8 万行 Python，42 条命令用到第二相机，在 25 个任务里被调用 998 次。

两个 agent 的权限被切得很干净：acting agent 的容器看不到仿真器、任务代码和评分代码，成功只由基准 checker 判定；optimizer 只能改 `tasks/⟨task⟩/tools/`，交付检查用禁用词表挡住任务名与物体名，不通过就回滚。

## 我的判断

这套设计站得住，主要靠三点。第一，把 ground truth 用架构隔离，而不是靠 prompt 约束：容器里没有仿真器、没有 key，agent 想作弊也没有通道，分数才可信。第二，薄壳换的是工具而不是脚手架，agent、prompt、基础接口、模型都固定，三角化与深度网络的对照才是干净的消融。第三，作者主动做了泄漏审计：七个任务的工具里残留了固定几何常量，用这些常量时它们过了 70 个重测布局里的 3 个，把常量换成 episode 内测量后重测，全部 0/10。把这件事写进正文，比多报两个点更有价值。

没报的成本有三块。推理开销很大，一集重测 739 s 对应 26 s 机器人时间，优化阶段累计读了近 5 亿输入 token，论文没有给出与学习策略推理延迟的对比。人力也没算：每任务 12 小时开发预算，25 个任务由作者写了 checker 说明，七个任务重测清零，说明结果对这批人工输入敏感。第三，运行参数没有消融：每布局最多改五次、开发只用十个布局、12 小时预算，这三项决定了工具能长到多成熟，论文没有给出更紧或更松时的曲线。

还有两处比较口径要留意。三角化与深度网络的对照跑的是开发布局（420 集），主表的 39.7% 跑的是新布局，所以表 1 的 38.3 与主表不能直接相减。能力图里各列也不是同一批布局：三角化一列在新布局上，深度网络与无工具两列在开发布局上，类别之间的排序可以参考，绝对差值要打折看。

模型规模与模型种类的影响完全没有测。整套结果只有一个模型（GPT-6-Astra，medium 推理强度），无工具基线还用了基准作者写的壳，这等于把「模型本身的空间判断」限制在别人的接口里。换一个更弱或更强的模型，工具库的形态大概率会变。

要照着做，有四条建议。复现时先跑审计脚本，把工具里的字面量与任务定义、日志逐个比对，再报分数。插入类任务要把测量塞进夹持过程，让工具在夹着零件时继续修正运动，而不是先测后动，论文自己把这一步列为下一步。步数预算必须把视角移动计入，否则主动感知的成本会被系统性低估。无工具基线要用同一个模型、同一套壳，比较对象才对齐。

这套工作在读场景和记忆上已经超过学习策略，短板落在接触。工具库的上限由「能否在接触中继续测量」决定，这条边界比 39.7% 这个数字更值得记住。
