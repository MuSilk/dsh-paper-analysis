读得懂手册，拼不成结构：JARVIS 的 50 道物理装配考题

引子

桌面上是一座拼到一半的乐高结构，74 块砖已经就位，旁边散着这一步要用的零件。手册画面上只有零件图、箭头和凸点标记，没有语言指令。机械臂要从散砖里挑出形状和颜色都对的那一块，抓起，对准凸点，压到位，再翻下一步。

这是 JARVIS 里刻意留下的长程样例：初始 74 块，要再放 29 块，最终 103 块，\(S_{\mathrm{scene}}=0.244\)、\(S_{\mathrm{act}}=1.000\)，难度 \(D=0.773\)，在 1,067 个候选任务里归一化难度为 1.00，归入 Hard 档。整段装配只给手册图像和一张顶视 RGB 观察，没有语言指令，也没有参考动作轨迹。

单步动作本身不难。附录在任务 000003 上对比三个模型，它们都生成了完整的接近、抓取、转移、放置序列，软分数分别是 66.67、63.94 和 67.39，差距只在最后几毫米的位姿。难的是越往后：每次落砖都改变工作台，早期偏差把后面的凸点挡住，机械臂还会蹭到已拼好的邻砖。

论文记录的两类失败都发生在这里。Claude Opus-4.5 和 GPT-5.1 在非反思设置下都抓起目标砖，却在转移和放置时撞上周围结构，邻砖移位、翻倒、散落，工作台状态与程序开头假设的逐步分离，没有新观察可以重规划，误差沿剩余动作传下去，最终得分 0.43 和 0.00。另一类更早：抓取没夹牢，后面所有放置都建立在错误状态上，非反思下整段得 0.00，换成结构化反思后回到 17.05。

问题背景

这类任务被拆在四个层次上，每一层的输出是下一层的输入。

层级 要回答的问题 本文的术语 边界
手册理解 每张步骤图对应哪些零件、装到哪里 视觉手册 \(\mathcal{M}=\{I_0,\ldots,I_T\}\) 只解出步骤与零件的对应，不涉及机器人
装配规划 先装哪块、目标位姿在哪、能不能装上 目标结构 \(s_T\)、动作砖 输出结构化表示，不含运动
物理执行 在当前工作台上抓取、搬运、落位 状态转移 \(s_{t+1}=\mathcal{T}(s_t,a_t)\) 需要运动规划、碰撞处理与状态估计
评测 完成多少、偏了多少、结构是否合法 软分数 \(S_i\) 从最终物理结构算分

已有路线大致分三派。

路线 代表工作 做法 卡住的地方
视觉装配规划 MEPNet、Manual-PA、Neural Assembler、AssemLM 从手册图、多视角或点云预测零件位姿与装配顺序 输出是表示，不落到机器人
手册驱动的执行系统 Manual2Skill、Manual2Skill++、BrickCraft、ManualVLA 把手册转成装配图或子目标，再接运动规划或学到的操作技能 各自绑定表示与控制栈，横向不可比
执行基准与反馈 AssemblyBench、WorkBenchMark、CaP-X、ENPIRE 评装配顺序、目标结构搭建，或不同工具抽象和反馈下的编码智能体 少见只给手册、全流程闭环、按最终结构打分的设定

三派各自把一段做扎实，合起来缺一个共同底座：视觉规划停在执行之前，执行系统各绑自己的控制栈，基准又把手册绕了过去。没被回答的问题是，把手册原样交给通用多模态模型，让它决定下一步、写程序、执行、看结果、纠错，最后拼出来的结构能打多少分。这既需要可比的任务，也需要不偏向任何具体方法的评分口径。

核心思想

这套方法借的是工具接地的编码智能体（code-as-policy）框架：模型不预测关节轨迹，而是写一段调用机器人原语的程序，环境执行后把观察和异常还回来。

它把原来的问题换掉了。模型能不能读懂手册很难直接测，因为没有标准答案的动作序列；换成「模型写的程序在工作台上跑完之后，最终结构能不能通过结构感知评分」，可测的东西就挪到结果端。手册从必须被完整解析的输入变成可反复回查的说明书；动作从必须与参考轨迹对齐，变成只要最终砖块落在容差内。

方法

机制一：分段任务与难度分层（Segment Decomposition and Difficulty Stratification）

它治的是把整本手册当成一条 episode 带来的问题：长度不可控，难度不可比，长尾任务把均值拖平。

做法是把 8,987 个乐高场景的搭建过程切成连续片段，每段给定半成品初始状态、对应手册片段、所需零件和目标结构，共 236,679 个任务，每个任务操作 1 到 43 块砖。手册另渲染了多种视觉风格，测外观变化的鲁棒性。

难度由两个因子合成：\(S_i^{\mathrm{scene}}\) 与 \(S_i^{\mathrm{act}}\) 分别是初始砖数与动作砖数的归一化值，按最小最大值缩放到 \([0,1]\)：

\[D_i=\alpha S_i^{\mathrm{scene}}+(1-\alpha)S_i^{\mathrm{act}},\qquad \alpha=0.3\]

动作砖拿 0.7 的权重，因为定位、抓取和状态估计误差会沿步骤累积。从 1,067 个校验任务按 \(D_i\) 排序，底部 40% 为 Easy，中间 30% 为 Medium，顶部 30% 为 Hard，每层均匀取样并优先选不同源模型的任务，得到 50 个任务，20/15/15。

机制二：结构感知评分（Structure-Aware Scoring）

它治的是二值成功判据的粗糙：砖放上去但偏了几厘米，和砖完全没动，在成功或失败口径下都是 0 分。

位姿分对每块必需砖算位置、垂直、朝向三个误差，各用高斯核转成软分

\[s_j^{k}=\exp\left[-\frac{1}{2}\left(\frac{e_j^{k}}{\sigma_k}\right)^{2}\right],\qquad k\in\{\mathrm{pos},z,\theta\}\]

再按 \(\lambda_{\mathrm{pos}}+\lambda_z+\lambda_\theta=1\) 加权平均。砖没被移动过或没出现，该项拿 0 分。

完成分另立口径：砖被移动超过 5 mm、到目标不超 5 cm、结束时不被夹爪夹着，三条同时满足才计一块；合法性再看砖是否留在桌面区内。质量分把两者线性合成，一块必需砖都没动过则整题记 0。时间惩罚只在超预算后启动，预算 \(T_i=T_{\mathrm{base}}+N_iT_{\mathrm{brick}}\)，因子为 \(\alpha+(1-\alpha)\exp(-\max(0,t_i-T_i)/T_i)\)，有下界，慢一点不会清零。

机制三：接地程序生成（Grounded Program Generation）

它治的是每来一种新任务就要重采机器人轨迹的成本，低层轨迹绑死在具体运动学和夹爪接口上。

agent 拿到手册和当前观察后，先调感知接口定位候选砖、判断装配到哪一步，再把手册的一步落成工作台里的目标位姿，然后生成 Python 代码，从技能库选择和参数化抓取、搬运、放置技能。技能内部负责位姿校验、抓取确认、避障运动和失败处理，异常作为结构化结果返回。

接口是硬约束：程序不许重定义 API，不许直接给未经验证的抓取坐标、逆运动学目标或夹持力。模型只在选哪块砖、放到哪这一层做决策，低层可行性由共享技能保证，全程不训练任务专用策略，也不更新参数。

机制四：执行记忆与反思（Execution Memory and Reflection）

它治的是没有反馈时一次抓空、后面全错的传播问题。非反思模式下程序一次生成、一次执行，中途发生什么都不再回看。

每轮执行后，系统把计划、代码、API 调用、物体状态以及抓放和运行结果记进结构化记忆，进下一轮前压缩成任务相关摘要；真值位姿与评分只留给外部评测器。

反思有两种设置。标准反思只用当前任务的观察、代码和执行反馈诊断失败并改程序；反思加先验任务经验额外给一份从训练任务日志总结的通用教训，包含常见失败、有效策略和 API 用法。两者都不改参数。

最反常的一处是失败动作数与总分不同向。GPT-4o 每任务只有 3.50 次失败动作，九个模型里最少，总分却只有 11.55；DeepSeek-V4.1 每任务 4.26 次失败，总分 17.39 最高。少做无效操作和做出结构进展是两件事，前者可以靠保守策略拿到，后者要求每一步都真的推动装配。GPT-5.1 是另一个方向，程序有效率 96.00，每任务却有 14.84 次失败动作，总分仍到 14.99。

反思的结论比预期悲观。标准反思第一轮低于无反思：Gemini-3-Pro 从 17.13 掉到 12.77，Claude-Opus-4.5 从 17.04 掉到 13.83，DeepSeek-V4.1 从 17.39 掉到 9.84；去掉时间惩罚后分别是 13.47、15.50、11.52，仍低于无反思。DeepSeek-V4.1 从 R1 的 9.84 升到 R2 的 13.04，还是没回到 17.39。先验任务经验把 R1 抬到 18.63、18.22、17.99，Gemini-3-Pro 到 R2 再涨 2.25%，R3 回落到 17.57，Claude-Opus-4.5 的 R1 到 R2 反而跌了 20.47%。

计划与执行的落差在接地实验里最明显。加上结构化 3D 描述子后，Gemini-3-Pro 的位置误差从 78.08 mm 降到 16.76 mm，覆盖率却从 15.44% 降到 13.13%；九个模型里最高覆盖率只有 25.10%，全流程最好总分只有 17.39。落位估得准，不等于把砖放上去，也不等于放上去之后结构还对。

长程敏感性是另一条稳定规律。初始复杂度低时，装配长度从 1 到 2 块增到 3 到 5 块，宏平均从 40.01 掉到 18.29；长度固定在短程，初始结构从 0 到 29 块增到 79 块以上，宏平均从 40.01 掉到 16.64。两个因子都高的格子最差，宏平均只有 4.43。初始复杂度的影响更渐进，也更依赖具体结构。

恢复实验单独看 25 个扰动任务，平均分只从 54.73 升到 55.14，涨 0.42 分；8 个任务变好，最大涨幅 26.22 分，最大跌幅 15.99 分。恢复能力在任务之间高度不均匀，均值几乎被正负抵消。

把目标直接给出来，执行能力又是另一幅图景：真值引导的有效动作评测里，Gemini-3-Pro 用 150 个动作拿到 24.25，GPT-OSS-120B 用 187 个动作拿到 23.76，DeepSeek-V4.1 是 142 个动作 22.66，GPT-4o 只有 86 个动作 13.20。单个动作可以做得不错，全流程分数却很低，缺口出在选步、定位和连续状态维护上。

工程实现细节

仿真侧用 NVIDIA Isaac Sim 6.0.1，机器人是 Franka Emika Panda 配平行夹爪，乐高砖建成带碰撞几何、接触和摩擦的动态刚体。观测只有顶视规划相机的 RGB 加关节状态；臂和夹爪通过 ROS 2 控制，运动默认走 cuMotion/RMPflow，MoveIt 可作备选。

API 是一组受约束的技能：场景观察、物体接地、几何推理、基于点云的抓取估计、运动规划、夹爪控制、抓放执行。每个函数规定输入、返回观察和执行约束，模型只能组合调用，不能直接读写仿真器状态。3D 描述子由技能工具生成，是砖块几何与空间属性的紧凑表示。

执行有两种模式：非反思一次生成完整程序；反思逐步闭环，每次抓放后拿新观察和结构化反馈，比对预期进度，再决定继续、改程序、纠正或终止。

训练集有 20 万以上任务，来源包括合成的乐高 3D 数据集、LDraw 模型，以及真实手册配对应的 3D 结构；每块砖的动作标注和中间状态真值都有记录，由三名人工评审复核。训练集平均 4.94 块动作砖，中位 4，超过 20 块的占 0.49%，最长 43 块；初始砖数 0 到 740，中位 57，30 到 78 块与 79 到 149 块两组分别占 30.4% 和 22.2%；两个因子的 Pearson 相关系数只有 0.181。

校验池由 48 个源模型转成 1,277 个任务，筛后剩 1,067 个，平均 4.82 块动作砖，最长 29 块；初始砖数 0 到 411，均值 80.44。基准按难度从这个池子抽样，不是独立切分，50 个任务也覆盖不了超过 300 块初始砖的极端格子。

评分的几个关键超参没有给数值。正文说高斯核带宽 \(\sigma_k\)、位姿三项权重 \(\lambda\)、质量分权重、时间惩罚系数、\(T_{\mathrm{base}}\) 和 \(T_{\mathrm{brick}}\) 都在附录报告，但 HTML 附录 A 到 D 里只有流程、数据分布和案例，没有这些数。交互轮数预算和 wall-clock 预算同样只写了预定义。

我的判断

这个设计站得住的地方在于评测对象选对了。装配的成败最终体现在结构上，而不是动作序列像不像参考轨迹；按最终结构打分，就绕开了逐任务采轨迹这个最贵的环节，通用模型可以直接进场。工具库那一步也聪明，把 VLA 的轨迹采集问题换成 API 编排问题，技能承担可行性，模型只负责选砖和目标位姿，这是九个模型换原语后平均分从 7.88 跳到 14.71 的原因。

没报的东西不少。\(\sigma_k\)、\(\lambda\)、时间惩罚系数和两个时间常数缺失，分数不可复算，跨论文比较只能停在同代码内部；每个 episode 的时长、token 消耗、每模型跑几次、有无随机种子和方差，全都没有。50 个任务意味着一题约值 2 分，单任务波动会直接进均值，而表里给到两位小数，精度比样本量支撑的更高。

完成阈值值得单独说。乐高凸点的配合是毫米级，5 cm 的完成判定比真实拼接松了一个量级，砖落在 5 cm 内就算完成，结构上可能根本没咬合。论文案例印证了这点：先验任务经验把朝向分从 24.57 抬到 80.63、位置分从 96.20 抬到 99.72、总分从 45.12 到 56.32，完成分仍然是 0。软分数更适合读成接近目标的程度，不适合读成拼成了的比例。

排名也被工具库改写。通用 API 下 Claude-Opus-4.5 以 13.83 领先，DeepSeek-V4.1 只有 8.49；换上任务导向原语后 DeepSeek-V4.1 到 17.39，反超 Claude-Opus-4.5 的 17.04。论文自己也提到，低层 API 下的评测会把推理能力和工具编排混在一起。

后续工作有几件事值得先做。把 \(\sigma_k\) 与 \(\lambda\) 写进配置并公开，让分数可复算；每个模型至少跑三次并报方差，别把 50 个任务的单次结果当成稳定排名；反思轮数预算和 wall-clock 预算分开记，否则分不清是模型不会改还是没时间改；另外单独统计结构连接真正形成的比例。
